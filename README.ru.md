# damstack

[English](README.md) | Русский | [Español](README.es.md)

Свой сервер, настроенный и обслуживаемый с вашего Mac одной программой.

Вы арендуете сервер, отвечаете на несколько вопросов, и damstack превращает
его в личную платформу: вход только по вашему ключу, доступ через вашу
собственную сеть WireGuard, Nomad, Consul и Vault для запуска приложений,
сертификаты Let's Encrypt и ночные бэкапы, которые копируются на ваш Mac.
Дальше на неё ставятся приложения, например собственный почтовый сервер, —
каждое одной командой.

Разбираться в серверах не нужно. damstack сам спрашивает, что ему нужно,
говорит, что делает, и следит, чтобы сервер оставался таким, каким вы его
настроили.

## Что понадобится

- Mac на Apple silicon или Intel с [Homebrew](https://brew.sh).
- [Приложение WireGuard](https://apps.apple.com/app/wireguard/id1451685025) —
  для приватной сети между вашими устройствами и сервером.
- Сервер с Ubuntu 24.04 у любого провайдера: его IP-адрес и root-пароль,
  который выдаёт провайдер. Хватит 2 CPU, 4 ГБ памяти и 20 ГБ диска.
- Домен, DNS которого в [Cloudflare](https://www.cloudflare.com), и API-токен
  там с правом менять DNS этого домена. Другие DNS-провайдеры тоже работают,
  по имени, которое им даёт [lego](https://go-acme.github.io/lego/dns/).
- Для почты: провайдер, который разрешает серверу отправку через порт 25.
  Многие закрывают его, пока не попросишь.

## Установка

```bash
brew install eugene-panin/tap/damstack
damstack
```

Первый запуск проверяет Mac и говорит, чего не хватает и где это взять.
Инструменты, которыми он работает, — OpenTofu, Ansible и restic — damstack
скачивает один раз и держит отдельно от всего остального на Mac. Docker не
нужен.

## Первый сервер

```bash
damstack deploy hashi
```

damstack спросит адрес сервера, домен для админок (например,
`admin.example.com`), ваш email для Let's Encrypt, токен Cloudflare и
устройства, которым можно ходить на сервер, например `laptop` и `phone`.
Потом, один раз, root-пароль сервера, чтобы положить туда ваш SSH-ключ;
пароль нигде не сохраняется.

Дальше, примерно за десять минут:

1. **Защита сервера**: свой пользователь, вход только по вашему ключу, root и
   пароли выключены, файрвол, автоматические обновления безопасности.
2. **Платформа**: сеть WireGuard, Consul, Vault и Nomad, Docker,
   синхронизация времени и ночной бэкап.
3. **Traefik и админки**: сертификат на `*.<ваш домен>`, страницы открываются
   только через WireGuard.
4. **DNS-записи**: публикуются сами.

Посередине он остановится, чтобы подключить ваш Mac к приватной сети:

```bash
damstack tunnel show laptop
```

кладёт конфигурацию в приложение WireGuard; для телефона
`damstack tunnel show phone --qr` показывает код для сканирования.

В конце damstack покажет админки — `nomad.`, `vault.` и
`consul.<ваш домен>` — и как получить токены к ним:

```bash
damstack token nomad
```

`damstack trust` делает так, чтобы Mac доверял сертификатам приватной сети, и
серверы открывались и по своим адресам.

## Приложения

```bash
damstack app add mail
damstack deploy
```

спросит, что нужно приложению, и запустит его на вашем сервере. В библиотеке
есть **mail** — собственный почтовый сервер на [Stalwart](https://stalw.art)
(ящики для каждого домена, DKIM, MTA-STS, IMAP и SMTP с сертификатами и
DNS-записи, по которым почтовые клиенты находят настройки сами), **odoo** и
общие сервисы, на которых строятся приложения: **postgres**, **nats**,
**seaweedfs** (S3), **loki**, **mimir** и **grafana**. Приложение из своего
репозитория, публичного или приватного, добавляется так же.

Приложения работают в контейнерах на Nomad, у каждого только те права,
которые ему нужны, и могут войти в service mesh Consul: тогда база данных
пускает по mTLS только приложения, названные в её настройках.

Ключи приложения, например API-ключи LLM, — его секреты: их спрашивают при
добавлении (необязательный можно не задавать), меняют командой
`damstack secret set`, хранят зашифрованными и отдают через Vault только тем
сервисам, которые ими пользуются. Смена ключа перезапускает только их.

## В терминале

`damstack deploy` показывает полноэкранный вид: все шаги, задачи текущего и
сколько их осталось, план, который нужно одобрить, прежде чем что-то
изменится, что упало — словами упавшего инструмента, — и в конце все адреса,
которые обслуживает сервер, с проверкой. Если Nomad изменит сервис так, что
изменение вступит в силу только после перезапуска, план скажет об этом и
предложит перезапустить. `--plain`, пайп или CI оставляют обычные строки.

## Вместе

Когда проект поднят, его состояние живёт на сервере, а не на одном ноутбуке:
деплоить его может любой, у кого есть проект. Изменения берут лок: второй
деплой ждёт своей очереди и показывает, чей деплой он ждёт. `--break-glass`
деплоит без лока, по состоянию на вашем Mac, — только чтобы чинить сам
сервер.

## Каждый день

| Что нужно | Команда |
| --- | --- |
| Увидеть проекты и то, что требует внимания | `damstack` |
| Проверить, что сервер такой, как вы его настроили | `damstack status --live` |
| Поменять настройку | `damstack edit`, затем `damstack deploy` |
| Задеплоить снова, меняя только то, что отличается | `damstack deploy` |
| Задеплоить только приложения, не трогая сервер | `damstack deploy --apps-only` |
| Дать приложению ключ или посмотреть, какие заданы | `damstack app keys sauron` |
| Увидеть все секреты, самые рискованные первыми, и сменить выбранные | `damstack secret` |
| Добавить или убрать устройство приватной сети | `damstack tunnel add phone`, `damstack tunnel remove phone` |
| Выдать устройству или серверу новые ключи | `damstack tunnel rotate phone` |
| Открыть shell на сервере или выполнить там команду | `damstack ssh`, `damstack ssh -- uptime` |
| Посмотреть всё, что damstack запускал | `damstack history` |
| Переименовать проект на Mac | `damstack rename old new` |

Если проектов несколько, назовите нужный, например `damstack status ovh`, или
сделайте его текущим: `damstack use ovh`.

## Бэкапы

Сервер делает бэкап каждую ночь: данные Consul, Vault и Nomad и данные каждого
приложения. damstack копирует бэкапы на Mac каждый час, пока он включён;
`damstack backup status` показывает их, а главный экран предупреждает, когда
они устаревают.

Всё, что нужно, чтобы вернуть проект, лежит на вашем Mac. Сделайте
**recovery kit** — один зашифрованный файл с проектом и его паролем — и
храните его в другом месте, например в облаке, а фразу-пароль от него — в
менеджере паролей:

```bash
damstack backup kit
```

На другом Mac `damstack backup open <kit>` возвращает проект.

## Если сервер потерян

Арендуйте новый сервер, укажите его адрес в проекте и восстановите:

```bash
damstack edit          # новый адрес в разделе server
damstack restore
```

damstack настроит новый сервер так же, как первый, и вернёт Consul, Vault и
данные каждого приложения из последнего бэкапа на Mac. Ключи, токены, ящики и
письма — как были.

## Где что лежит

Проект — это каталог `~/.damstack/<имя>`:

- `stack.yaml` — единственный файл, который нужно править; `damstack edit`
  открывает его и проверяет;
- `vault.yml` — секреты, зашифрованные; пароль к ним лежит в
  `~/.config/damstack/projects/<имя>`, вне проекта;
- состояние платформы и история того, что запускалось.

Чтобы удалить damstack: остановите ежечасное копирование каждого проекта —
`launchctl bootout gui/$(id -u)/dev.damstack.backup.<имя>` — и удалите
`~/Library/LaunchAgents/dev.damstack.backup.<имя>.plist`; затем
`brew uninstall damstack` и удалите `~/.damstack`, `~/.config/damstack` и
`~/.cache/damstack`. Первые два каталога или recovery kit храните, пока
работает хоть один ваш сервер: без них им нечем управлять.

## Ограничения сейчас

- Только macOS и один сервер на проект.
- Полноэкранный вид пока только у деплоя и секретов; остальные экраны его
  дизайна — в следующих релизах.
- Новые версии платформы или приложения ставятся вручную; команды
  `damstack upgrade` пока нет.
- Проверено на OVH и Google Cloud.
